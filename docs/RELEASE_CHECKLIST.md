# Release checklist

## GitHub 공개 전

- `git remote -v`에 게시하려는 저장소의 `origin`만 있는지 확인합니다.
- `git status --short --ignored`로 `build/`, `run/`, `.gradle/`, `.toolchains/`, IDE 설정과 로그가 추적되지 않는지 확인합니다.
- 첫 공개라면 예제 템플릿 이력을 그대로 내보내지 말고 Hangul의 검토된 파일로 새 초기 커밋을 만듭니다.
- 추적 파일과 커밋 이력에 토큰, 비밀번호, 로컬 절대 경로, 실행 로그, 개발 대화나 임시 메모가 없는지 검사합니다.
- `README.md`의 로더별 버전, 해당 JAR 메타데이터와 파일명이 일치하는지 확인합니다. 모든 로더의 번호를 일괄적으로 올리지 않습니다.

## 플랫폼별 배포 범위

- `gradle.properties`의 `mod_version`은 이번 릴리스 번호입니다. `fabric_mod_version`, `neoforge_mod_version`, `forge_mod_version`은 각 파일의 실제 버전이며 독립적으로 유지합니다.
- 실행 코드가 바뀐 플랫폼만 번호를 올립니다. 2026-10-11부터 지원 선언·리소스·버전만 바뀐 파일도 새로 배포하지 않습니다. CI·문서·압축 시간·순서만의 변경도 배포 사유가 아닙니다.
- 공통 실행 코드를 수정했다면 영향을 받는 모든 플랫폼의 파일을 갱신하고 검사합니다. 코드 변경 없이 지원만 재검증한 경우에는 기존 공개 파일의 설치 가능 범위와 구분해 기록하고 다음 코드 업데이트에 지원 선언을 반영합니다.
- 이번 `mod_version`과 같은 플랫폼 버전만 업로드 대상입니다. Fabric 파일은 Quilt와 공유합니다. 다른 플랫폼은 기존 공개 파일을 계속 안내합니다.
- 이전 공개 JAR을 별도 비교 디렉토리에 내려받고 아래 게이트를 실행합니다. 비교 디렉토리에는 선택한 플랫폼당 이전 파일 하나만 둡니다.

```powershell
$candidateJars = @(
    'build/libs/hangul-1.3.0-beta.11-fabric.jar',
    'platforms/neoforge/build/libs/hangul-1.3.0-beta.11-neoforge.jar',
    'platforms/forge/build/libs/hangul-1.3.0-beta.11-forge.jar'
)
python scripts/verify-artifacts.py @candidateJars
python scripts/stage-release.py @candidateJars --previous-dir .toolchains/release-baseline-beta11 --output-dir build/release/1.3.0-beta.11
```

위 예시는 공통 입력 코드가 바뀐 beta.11 후보를 공개 beta.10 파일과 비교합니다. 특정 플랫폼만 코드가 바뀌었다면 버전 설정과 선택 목록도 그 플랫폼만 포함하도록 맞춥니다. 스테이징은 업로드가 아니며, 실사용 검사와 릴리스 문구 검토를 마친 뒤 게시합니다.

게이트는 전체 내용과 실행 클래스 바이트를 대조합니다. 실행 클래스가 같다면 새 지원 버전·리소스·버전이 달라져도 새 파일을 거부합니다. ZIP 구성과 텍스트 줄바꿈 차이, 미선택 플랫폼, 이전 파일 누락, 중복·누락된 플랫폼과 배포 폴더의 잔여 파일도 배포 사유로 인정하지 않습니다. 기존 파일이 다른 내용이면 덮어쓰지 않습니다.

GitHub에는 게이트가 만든 폴더의 JAR과 체크섬만 올리고, Modrinth에서도 같은 JAR만 업로드합니다. 전체 CI 산출물(`verified-*`)을 일괄 배포하지 않습니다. 기존 Forge·NeoForge 릴리스는 삭제하거나 다시 올리지 않습니다.

CI는 모든 로더의 26.2 기준 빌드·실제 로더 적용·패키지를 검사합니다. `scripts/verification-matrix.py`가 선언 목록에서 전체 Fabric·Quilt, 대표 Windows, 최소 Fabric 및 시험판 Fabric 대상을 생성합니다. 새 스냅샷을 추가하면 대표·최소 로더 검사에도 자동 반영됩니다. NeoForge·Forge는 게임 버전별 작업으로 나눠 동일 후보를 검사하며, 패키지 게이트는 모든 호환성 작업의 성공을 기다립니다. 플랫폼 빌드는 35분, 게임별 플랫폼 검사는 25분, 개별 로더 실행은 3분으로 제한합니다.

`updates.yml`은 수동 실행 또는 주간 일정으로 공식 게임·로더 메타데이터를 조회합니다. 결과는 읽기 전용 보고서이며 저장소·지원 선언·릴리스·Modrinth를 자동 변경하지 않습니다. 개발 소스의 추가 대상과 공개 파일의 지원 누락을 따로 표시합니다. 아직 선언하지 않은 26.x용 NeoForge·Forge가 나오면 검토 대상으로 보고하며, Maven의 목록 순서만으로 최신 버전을 판단하지 않습니다.

## 라이선스와 브랜드

- 코드·번역·이미지·아이콘의 출처와 재배포 권한을 확인합니다.
- 외부 프로젝트의 코드를 포함했다면 해당 라이선스의 고지·소스 공개 의무를 충족하기 전에는 배포하지 않습니다.
- 출처가 불명확한 파일은 저장소와 릴리스 JAR에 넣지 않습니다.
- 프로젝트 아이콘은 독자 제작물만 사용하고 Minecraft 또는 다른 모드의 로고·텍스처·표장을 사용하지 않습니다.
- Minecraft 비공식 프로젝트 고지가 README와 배포 페이지에 유지되는지 확인합니다.

## 빌드와 패키지

```powershell
.\gradlew.bat clean build --no-daemon
```

- 조합·검색 테스트, 바이너리 검사와 실제 Mixin 적용·위젯 검사가 모두 성공해야 합니다.
- `verify-compatibility.ps1`로 동일한 배포 후보 JAR을 전체 선언 버전에서 검사합니다.
- 멀티로더 릴리스는 `verify-multiloader.ps1 -FullMatrix`와 패키지 검사를 통과해야 합니다. 선택 릴리스는 `-Platforms fabric`처럼 해당 플랫폼을 지정합니다. 로더별 최종 파일 하나를 고정하고 버전별 검사에서 다시 빌드한 파일로 바꾸지 않습니다.
- 배포하는 로더는 모두 현재 실행이 남긴 성공 기록과 후보 JAR의 SHA-256이 일치해야 합니다. 프로세스 종료 코드나 이전 실행의 성공 기록만으로 통과 처리하지 않습니다.
- Fabric·Quilt의 다른 게임 버전을 검사할 때는 26.2에서 만든 `build/compatibility/verification.jar`를 `-PverificationFixture`로 고정합니다. 대상 게임에 맞춰 모드 소스를 다시 컴파일하거나 검사 중 후보를 바꾸지 않습니다.
- Quilt는 Fabric 파일, NeoForge·Forge는 각 전용 파일로 배포합니다. 플랫폼 표시와 실제 JAR 메타데이터를 대조합니다.
- NeoForge 26.2용 메타데이터는 `iconFile`을 사용하고, 사용 중단된 `logoFile`이 다시 포함되지 않도록 패키지 검사로 차단합니다.
- `custom.hangul:tested_game_versions`는 Mojang 버전 ID, `depends.minecraft`는 Fabric 정규화 버전으로 작성합니다. 두 목록의 일치 검사가 통과해야 합니다.
- `build/libs`의 배포 JAR을 열어 소스, 로그, 캐시, 테스트 클래스, 로컬 경로가 포함되지 않았는지 확인합니다.
- 새로 추가한 게임 대상에서 믹스인 오류 없이 메뉴에 진입하는지 확인합니다. 실행 코드 변경 시에는 26.2 기준 클라이언트도 검사합니다.
- Forge JAR과 검사 전용 JAR에 유효한 `pack.mcmeta`가 있어야 합니다. 선언한 모든 게임 버전에서 클라이언트 리소스·서버 데이터 형식 파서 검사를 통과해야 합니다.
- 선택적 위젯 변경은 `scripts/verify-mod-compatibility.py`로 고정한 실제 모드 파일에서 검사합니다. 알려진 외부 모드 실패의 재현과 지원 통과를 구분합니다. 자동 프로필의 실패를 무시해 릴리스를 통과시키지 않습니다.
- Forge 시작 경고가 있으면 배포를 중단합니다. 경고 표시를 끄거나 메뉴로 넘어간 것만으로 통과 처리하지 않습니다. 별도 로컬 월드에서 블록 드롭, 리소스 재로딩, 저장·종료까지 검사합니다.
- 실제 설치 폴더에는 `hangul` 또는 이전 별칭 `hangeul`의 활성 JAR이 합계 하나만 있어야 합니다.

## Windows IME 수동 검사

26.4 Snapshot 5의 `Prefer DXGI Present`는 재시작 후 적용됩니다. 설정 표시가 켜졌다는 이유만으로 현재 실행을 DXGI 검사로 계산하지 않습니다. 꺼짐·켜짐 각각에서 별도 재시작한 뒤 조합·후보창·창 전환을 확인합니다.

`scripts/prepare-native-client.py`는 공식 체크섬을 확인한 라이브러리와 전체 에셋으로 `.toolchains/native-clients/` 아래 별도 실행 환경을 준비합니다. 실제 계정 인증 정보를 읽지 않으며, 사용자 설치·설정·월드를 교체하지 않습니다. 오프라인 실행의 Realms 인증 경고는 입력 오류와 구분합니다.

1.3.0-beta.6의 잔여 수동 검사는 2026-09-06 테스터의 전체 완료 보고로 마감했습니다. 직접 관찰한 범위와 보고로 확인한 범위, 공개 전 남은 절차는 [배포 준비 상태](RELEASE_READINESS.md)를 따릅니다. 아래 목록은 이후 릴리스에서도 사용하는 검사 기준입니다.

1.3.0-beta.7은 2026-09-17에 로더별 26.3 기본 IME 실행, 대표 저장·화면 검사와 테스터의 명시적 확인으로 필수 실사용 검사를 마감했습니다. 실행 클래스가 바뀌지 않은 지원 선언 업데이트이므로 검사 범위는 변경 위험에 맞춰 정하며, 목록 전체를 모든 조합에서 반복한 것으로 표시하지 않습니다. 미관찰 항목과 증거 유형은 위 검증 기록에 남깁니다.

자동 위젯 검사는 실제 Windows IME와 그래픽 드라이버의 동작을 대체하지 않습니다. 새 릴리스는 26.2와 최신 지원 대상에서 다음 항목을 확인한 뒤 업로드합니다. beta.7에서는 26.3 정식판의 Fabric·Quilt·NeoForge를 각각 확인합니다.

새 로더는 각각 별도 프로필에서 검사합니다. 다른 로더에서 성공한 결과로 대체하지 않습니다. 기존 사용자 프로필과 월드는 변경하지 않습니다.

표지판·입력창의 자동 회귀 검사는 OS 입력을 주입하지 않고 변환된 게임 메서드를 검사합니다. 이 검사에서 한자 문자 이벤트나 방향키가 통과해도 Windows 후보창 선택·취소와 실제 키 전달을 통과로 표시하지 않습니다. 현재 결과와 미완료 항목은 [배포 준비 상태](RELEASE_READINESS.md)에 기록합니다.

- 채팅에서 조합·확정·취소, 문장 중간 입력, 선택 교체, Enter 중복 확정 여부
- 책의 자동 줄바꿈, 여러 줄 선택, 페이지 이동, 저장 후 다시 열기
- 표지판의 줄 전환과 저장, 한자 후보 선택·취소
- GUI 배율, 창 크기 변경, 전체화면 전환, 포커스 이동, Win+. 이후 입력
- 한/영 전환과 입력창 재진입 후 의도치 않은 영문 전각 입력 여부
- Windows 반각 옵션 변경은 [전각 영문 대응 검사](IME_WIDTH.md)의 F7 복구·설정 유지·다른 언어 보호 항목을 같은 후보 JAR로 추가 확인
- 단일행 입력창에서 F6을 켠 뒤 닫기·다른 입력창·중첩 검색창으로 이동
- 검색창에서 `rk`와 `Rk` 교체, 일반 영문·대문자 식별자·태그 검색
- F3+T 리소스 재로딩 후 조합 표시와 책 줄바꿈
