# Architecture

Hangul은 운영체제 IME를 대체하지 않고 Minecraft의 입력·렌더링 경계만 보완하는 클라이언트 모드입니다.

## 설계 원칙

- **Native first:** 한/영 전환, 조합 규칙, 한자 후보는 운영체제 IME에 맡깁니다.
- **임시 조합 상태:** 조합 중인 문자열은 화면에만 합성하며 실제 위젯 값이나 네트워크 패킷에는 넣지 않습니다.
- **이벤트 기반 처리:** 입력 이벤트와 검색 트리 재생성 시점에만 동작하고 상시 전체 목록 순회를 두지 않습니다.
- **작은 의존성 표면:** 선택한 로더 외 추가 런타임 라이브러리, 네이티브 DLL, 설정 프레임워크를 요구하지 않습니다.
- **실패 격리:** 명령어 검색 보조가 실패해도 바닐라 추천 결과를 그대로 반환합니다.

## 주요 경로

| 영역 | 처리 방식 |
| --- | --- |
| 단일행 입력 | `EditBox`의 preedit을 실제 커서 위치에 임시 합성 |
| 다중행 입력 | 조합 표시용 줄 목록을 캐시하고 렌더 구간에서만 교체한 뒤 원래 목록 참조 복원 |
| 표지판 | 줄별 선택·커서 좌표를 보존하면서 조합 문자열 렌더 |
| 한자 후보 | 현재 렌더 커서의 화면 좌표를 운영체제 입력 관리자에 전달 |
| 아이템·조합법 검색 | 언어 검색 트리 생성 시 원문과 초성 문자열을 함께 색인 |
| 자판 검색 | 짧은 질의만 두벌식으로 변환해 기존 접미 배열을 재사용 |
| 명령어 추천 | 현재 서버가 공개하고 사용을 허용한 리터럴만 자판·음차 규칙으로 보완 |

## 성능 모델

일반 입력에서는 preedit이 없으면 추가 문자열 합성을 수행하지 않습니다. 초성은 검색할 때마다 아이템을 순회하지 않고 검색 트리가 만들어질 때 한 번 추가됩니다. 질의 시에는 기존 `SearchTree`를 최대 두 번 조회하며, 두 결과가 모두 있을 때만 순서 보존 중복 제거 컬렉션을 만듭니다. 다중 단어 교집합은 전체 문구 검색 결과가 비었을 때만 실행됩니다.

명령어의 한글 보정은 입력에 한글이 있을 때만 비동기 후처리를 연결합니다. F6 비상 조합기는 키 분류와 겹받침 분리에 임시 객체를 만들지 않습니다. 기본 자동 입력에서는 F6 이외의 키에 화면 조회용 리플렉션을 사용하지 않습니다.

표시 문자열은 입력창별 단일 항목 캐시에 보관합니다. 책의 줄 목록은 표시 문자열·너비·글꼴 리비전이 바뀔 때만 계산하며, caret만 움직이면 기존 줄 목록을 재사용합니다. `FontManager.apply` 이후에는 모든 기존 레이아웃 캐시가 다음 사용 시 무효화됩니다. 조합 취소나 포커스 해제 시 해당 캐시가 참조한 본문과 줄 목록을 해제합니다.

세 입력 위젯의 렌더 구간은 `try/finally`로 감쌉니다. 줄바꿈 계산이나 원래 렌더 함수가 예외를 던져도 값·커서·선택 범위와 원래 줄 목록은 복원합니다. MixinExtras는 각 로더가 제공하는 것을 사용하며 별도 JAR을 동봉하지 않습니다.

F6 상태는 하나의 화면과 입력창에 귀속됩니다. 26.1의 `Minecraft.setScreen`과 26.2 이후의 `Gui.setScreen`에 대체 훅을 두며, 버전 검사에서는 둘 중 정확히 하나가 존재해야 통과합니다. 입력창이 포커스를 잃으면 조합 상태와 소유자 참조를 함께 지웁니다.

두벌식 검색은 창작 인벤토리·조합법 UI에서 원본 질의를 보존해 호출합니다. 바닐라 조회에는 소문자 질의를, 자판 변환에는 Shift 정보를 보존한 질의를 사용합니다. 태그 검색은 바닐라 경로를 유지하고 검색 트리 자체에는 초성 색인만 추가해 중복 자판 변환을 피합니다.

## 호환성 경계

기본 빌드 대상은 Minecraft 26.2와 Java 25입니다. Fabric·Quilt는 공용 JAR, NeoForge·Forge는 전용 JAR을 사용합니다. 바닐라 `EditBox`, `MultiLineEditBox`, `TextFieldHelper` 경로를 사용하지 않는 외부 모드의 자체 위젯은 별도 어댑터가 필요할 수 있습니다.

## 로더 분리

`src/main`과 `src/client`의 입력·검색 코드는 모든 로더가 공유합니다. 로더별 폴더에는 등록 정보와 빌드 설정만 두며, NeoForge의 클라이언트 등록 클래스는 별도 입력 루프나 이벤트 처리를 추가하지 않습니다. 검사용 진입점과 Mixin은 `src/verification`에서만 빌드합니다.

Forge에 포함된 Mixin이 지원하는 설정에 맞춰 Forge 파일만 Java 21 바이트코드를 사용합니다. 게임과 로더는 여전히 Java 25로 실행합니다. 로더를 바꾸기 위해 다른 Mixin이나 공용 호환 프레임워크를 모드에 내장하지 않습니다.
